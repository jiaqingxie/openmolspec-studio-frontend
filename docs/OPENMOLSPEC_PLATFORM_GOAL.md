# OpenMolSpec：数据集与深度学习平台总目标

更新：2026-11-17。此目标按用户最新指示替代原来的“接入现有模型并完善文档”总目标；已有任务、结果、数据审计和发布工作作为平台的第一阶段保留。

## 定位与论文暂题

**OpenMolSpec: A Million-Scale Dataset and Platform for Deep Learning in Chemical Spectroscopy**

构建可独立安装、可复用的 Python 包 `openmolspec`，让研究者用统一接口加载谱学数据、选择科学上相容的模型、推理、训练自己的模型并进行可复现评测。网页和中英文 Read the Docs 展示这个平台的真实能力。

设计参考 [DeepPurpose](https://github.com/kexinhuang12345/DeepPurpose) 的数据准备、模型初始化、训练与预测流程，以及 [DeepProtein](https://github.com/jiaqingxie/DeepProtein) 的多任务、数据加载和 notebook 教程组织。参考使用体验，保留谱学所需的单位、采集条件、原子对应和数据来源约束。

论文方向由最终证据决定，不承诺特定期刊接收。百万级必须指明计数对象与版本；不能将分子、谱图、构象帧和重复数据视图相加。

## 数据主线与归属

用户已明确：**从 OpenDataLab 清洗得到的数据是实验谱**。这部分作为平台的实验数据主线之一，不得归入计算数据，也不能描述成团队自行测量的新实验。

| 数据层 | 平台贡献与归属 | 当前规模证据 | 发布要求 |
| --- | --- | --- | --- |
| OpenDataLab / WanJuan 整理的实验 NMR | 外部实验测量，团队清洗、标准化、去重、划分 | 现有 standard-InChI 汇总：2,680,271 个结构身份；H 记录 2,722,790，C 记录 252,158 | 串起原来源、OpenDataLab 版本、清洗版本和原记录 ID；确认可公开哪些字段 |
| OpenMolSpec 计算数据 | 团队构建的计算谱与性质，分子来源库保留引用 | 现有 release 快照：1,158,074 个 InChIKey 身份；严格对齐视图 1,030,780 | 公开计算方法、几何配对、单位、质量控制、版本与分片 |
| 外部实验与基准数据 | NMRExp、NMRSpec/NMRTrans、NMRGym、MassSpecGym 等，分别署名 | 按实际版本列谱数、分子数、模态和划分，不并入团队原创数据量 | 能再分发才提供下载；否则提供官方获取流程和本地转换入口 |

上表全库数字来自已有汇总与 release 快照，并非本次重新扫描完整发布文件。测试视图的重新扫描证据保存在 `documentation/assets/dataset_audit.json`。实验与计算数据之间、不同实验来源之间的全库重叠尚需单独核验，不能据此声称两行数据都是独立的新分子。

每张 dataset card 应包含：原作者与提供方、实验/计算域、原始与清洗后计数、计数单位、核种/模态、字段与单位、缺失情况、来源分布、元素/大小/骨架分布、采集条件、去重规则、划分和泄漏检查、版本、引用、许可证与获取方式。

## 公开 Python 接口的目标

模块名称采用用户提出的单数形式：

```python
from openmolspec.dataset import molspectra
from openmolspec.model import NMRNet
```

**以上是要实现的接口契约，当前 release 尚未提供这两个入口。** 不把设计代码放进 Quick Start 冒充已可运行功能。内部现有 `openmolspec.datasets` 划分工具继续兼容。

| 层 | 目标能力 | 必须保留的信息 |
| --- | --- | --- |
| `openmolspec.dataset` | 数据集目录、版本化获取、校验、按需加载、筛选、既定划分、自定义数据导入 | 分子与谱图 ID、实验/计算域、模态、条件、来源、缺失掩码、许可 |
| `openmolspec.model` | `NMRNet` 等模型类；初始化、加载已发布权重、`predict`、支持时 `fit`、保存/加载 | 作者实现与版本、checkpoint 哈希、训练域、核种、输入要求、输出单位 |
| `openmolspec.task` | NMR、MS、IR/Raman、多模态任务的输入输出约束 | 所需/可选模态、已知分子式条件、候选池、原子编号约定 |
| `openmolspec.benchmark` | 在固定划分上运行评测、基线与可追溯结果导出 | 数据/权重/配置哈希、种子、样本数、排除项、指标定义 |

第一条贯通路径：加载一个真实 NMR 数据视图 → 查看字段、来源与划分 → 用相容的冻结 NMRNet H/C 权重预测 → 与参考谱比较并绘图 → 保存模型配置与结果。训练能力随后接到同一数据契约，不能只做一个空 `fit()`。

模型类不强迫所有后端使用同一运行环境；CPU/GPU 和作者依赖作为可选后端。普通数据加载不应下载权重、初始化 GPU 或依赖服务器绝对路径。MAGMa 是算法，跨溶剂现有路径是参考检索基线，应在能力表中明确标识，不伪装成可训练神经模型。

## 训练能力与当前运行边界

- 平台需让用户可以从头训练或微调适用的模型，并加载自己的数据。
- 训练入口显式接收训练/验证集；测试集不参与拟合、模型选择、归一化统计或校准。
- 同分子多谱、不同溶剂、不同构象以及重复来源应按身份成组，避免跨划分泄漏；提供固定官方划分和有明确适用范围的 scaffold/来源隔离方案。
- 每个后端单独声明能否训练、能否加载权重、支持的核种与输入条件；不以“有接口”代替能力验证。
- **本轮仍不启动真实训练、微调或拟合校准任务。** 当前先建设训练接口、配置与文档，保留用户此前“不训练”的执行约束。后续实验训练作为独立阶段安排。
- SpectraLLM、分子式预测和谱学 QA 继续暂缓。

## 工作顺序与验收

| 阶段 | 交付 | 验收条件 |
| --- | --- | --- |
| 1. 真实证据与数据说明 | 任务分类、输入输出、真实 notebook、Gallery、详细 Quick Start、数据分布、模型审计 | notebook 确实执行；图与指标可追溯；中英文、下载和 RTD 构建通过 |
| 2. 数据 API | `openmolspec.dataset.molspectra`、dataset cards、数据导入、校验、版本与划分 | 在干净环境中读到真实样本；无固定服务器路径；既定划分可复现；跨划分重叠检测 |
| 3. 模型 API | 先 NMRNet H/C，再封装现有 NMR/振动/MS 后端 | 新接口与原推理的同输入结果一致；缺模态/不相容域明确拒绝；保存来源与哈希 |
| 4. 自主训练能力 | 支持后端的配置、`fit`、保存/恢复、验证、用户自有数据教程 | 训练实现有可执行验证方案；正式发布前需独立授权的小规模训练验证；不拿缓存推理当训练成功 |
| 5. 独立基准与论文证据 | 数据质量、无泄漏划分、跨来源泛化、多模态收益和实验/计算迁移研究 | 报告完整样本与失败项、相同划分的基线、多种子或适当不确定性；小样本通路检查不能冒充论文主结果 |
| 6. 平台发布 | 可安装包、版本化数据/权重获取、双语 API 文档、notebook、网页入口、归档 | 干净环境安装/推理/文档验证；数据许可可追溯；GitHub 与 RTD 对应同一版本 |

阶段 1 已有本地实现与真实运行证据，尚需完成 notebook 执行与发布核验。阶段 2–4 是新增核心工作，不能在文档中提前标成完成。现有 34 项任务配置中 31 项活跃、3 项暂缓；这些数量不等于 31 个独立模型或 31 个均已科学验证的能力。

## 模型审计与潜在微调优先级

1. **29Si / 11B**：先核验专用权重、原始标签、单位/参考、溶剂和划分。现有 32 分子诊断 MAE 分别约 56.13 / 8.68 ppm，不能当作准确模型上线承诺。
2. **实验 NMR → 结构生成**：在解析、词表、给定分子式协议和独立划分确认后，研究跨来源适配。
3. **跨溶剂位移**：先准备带原子对应的配对实验数据及溶剂条件模型；当前参考检索基线本身不是可微调 checkpoint。
4. **缺模态 IR/Raman 路径**：区分四模态模型的消融与专用模型，按产品需求决定后续适配。
5. **Vib2Mol ITM 重排**：先解释同样本 top-1 退化，后续调整只能用独立开发集。

F/P 先解决适用域与参考约定，原子指认先补实验真值，MS 与构象到 IR/Raman 先扩大独立评测。这些都不自动等于需要微调。

## 论文需要的可核验贡献

重点证明实验谱清洗与统一、数据配对和质量控制、可复用多任务平台、以及可靠基准各自带来了什么。任务数量、网页数量和接口数量作为软件范围说明，不能替代科学贡献。

优先准备：数据来源与清洗流程图；实验/计算分开的规模与分布图；跨来源去重和划分重叠审计；任务与模型兼容矩阵；独立测试基线；真实输入输出和失败案例；可复现的软件与数据版本。平台 API 确认可运行后，再把教程改为简洁的类接口。
