# NMR 训练历史与评测重叠

2026-11-17 的审计对四份评测视图的全部 39,183 条记录，以及三个 NMR Transformer checkpoint 对应的现有训练/验证文件进行了比对，确认了分子重叠，并发现一项数据溯源差异。历史结果继续作为功能与诊断证据展示，不能作为未见分子上的独立基准。本审计不覆盖另一套 NMRNet H/C 或 MS 权重。

`mix_align_v2` 的两个文件与检索权重 `f90bd7…` 和中间生成权重 `aa2fea…` 记录的哈希均一致。全文件扫描覆盖 3,608,853 条训练记录、50,000 条验证记录。下表统计各文件中出现的评测结构身份数；未检查两列交集前，不可直接相加。

## 最终生成模型：文件指纹不一致

运行日志指向 `data/g1_all`，但 checkpoint 保存的训练哈希与 `data/g1_ne/train.jsonl` 相符，与当前 `g1_all/train.jsonl` 不符。历史训练代码直接复制 `verification.json` 中的哈希，没有重新计算文件内容，因此本审计不能认定任一文件就是当时实际读取的完整内容。最终验证文件的哈希匹配，与四份视图均无相同结构身份。

- Checkpoint-recorded training-file SHA-256: `bd2aa8f2f11f127462927b368569521f8ec0d38952955ef19bfd73b590f7e165`
- Current `g1_all/train.jsonl` SHA-256: `d06c16ee1e21ba4e3d6fe7c5a8037211bedb05997bd4940646b15875f87cdfb7`

作为现有文件统计，当前 `g1_all` 的 2,121,498 条记录与上述四份视图分别重叠 1,982 / 181 / 4,216 / 44 个结构身份；另有 16 条没有保存 InChI。这些数值不能冒充已核实的历史训练重叠。新 SDK 和原训练入口现均会在启动前重新校验文件哈希。本次未改写历史权重、清单或数据，也未执行训练。

## 身份定义与后续基准

比对采用保存的 standard-InChI 字符串，评测记录缺少身份时由 RDKit 生成。这是分子身份检查，不是相同原始谱图、骨架、所有立体异构体或专利家族的重叠检查；没有对每条训练记录重新生成 InChI。后续独立基准需要排除初始化各阶段相关训练/验证身份，解决末阶段文件差异，并明确采集条件与来源控制。即使 32 个候选的检索得到 100%，也不能替代这些工作。
